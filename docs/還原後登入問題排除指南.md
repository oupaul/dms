# 還原後登入問題排除指南

## 問題說明

還原資料庫後可能無法登入的原因：
1. **密碼雜湊格式不匹配**：還原的備份可能包含舊的 bcrypt 格式密碼，但系統現在使用 argon2
2. **帳號狀態異常**：帳號狀態可能不是 'active'
3. **資料庫損壞**：還原過程中資料庫可能損壞

---

## 快速診斷

### 方法 1：使用診斷腳本（推薦）

```bash
sudo ./check_accounts.sh
```

此腳本會顯示：
- 所有帳號清單及狀態
- 密碼雜湊格式（argon2 / bcrypt / unknown）
- 有問題的帳號
- 管理員帳號狀態
- 資料庫完整性

### 方法 2：手動檢查

```bash
# 進入資料庫目錄
cd /opt/folder-permission-system/databases

# 檢查所有帳號（使用 system.db 或 main.db）
sqlite3 system.db "SELECT id, username, full_name, role, status FROM accounts;"
# 或
sqlite3 main.db "SELECT id, username, full_name, role, status FROM accounts;"

# 檢查密碼雜湊格式
sqlite3 system.db "SELECT username, 
    CASE 
        WHEN password_hash LIKE '\$argon2%' THEN 'argon2'
        WHEN password_hash LIKE '\$2a$%' OR password_hash LIKE '\$2b$%' THEN 'bcrypt'
        ELSE 'unknown'
    END as hash_type
FROM accounts;"
```

---

## 解決方案

### 方案 1：使用密碼重置腳本（最簡單）

```bash
# 重置指定帳號的密碼
sudo ./reset_password.sh admin newpassword123

# 或互動式輸入
sudo ./reset_password.sh admin
# 然後按提示輸入新密碼
```

**注意**：此腳本會自動生成 argon2 格式的密碼雜湊。

---

### 方案 2：手動修改密碼（需要生成 argon2 雜湊）

#### 步驟 1：生成 argon2 密碼雜湊

創建臨時 Node.js 腳本 `generate_hash.js`：

```javascript
const argon2 = require('argon2');

async function generateHash() {
    const password = process.argv[2];
    if (!password) {
        console.error('請提供密碼作為參數');
        process.exit(1);
    }
    try {
        const hash = await argon2.hash(password);
        console.log(hash);
    } catch (error) {
        console.error('錯誤:', error.message);
        process.exit(1);
    }
}

generateHash();
```

執行腳本生成雜湊：

```bash
cd /opt/folder-permission-system
node generate_hash.js your_new_password
```

**輸出範例**：
```
$argon2id$v=19$m=65536,t=3,p=4$...
```

#### 步驟 2：更新資料庫

```bash
cd /opt/folder-permission-system/databases

# 更新指定帳號的密碼（使用 system.db）
sqlite3 system.db "UPDATE accounts SET password_hash = '生成的雜湊值' WHERE username = 'admin';"

# 驗證更新
sqlite3 system.db "SELECT username, substr(password_hash, 1, 20) as hash_preview FROM accounts WHERE username = 'admin';"
```

---

### 方案 3：修改帳號狀態

如果帳號狀態不是 'active'，需要先啟用：

```bash
cd /opt/folder-permission-system/databases

# 查看帳號狀態（使用 system.db）
sqlite3 system.db "SELECT username, status FROM accounts;"

# 啟用帳號
sqlite3 system.db "UPDATE accounts SET status = 'active' WHERE username = 'admin';"

# 驗證
sqlite3 system.db "SELECT username, status FROM accounts WHERE username = 'admin';"
```

---

### 方案 4：重新建立管理員帳號

如果管理員帳號完全無法使用，可以重新建立：

```bash
cd /opt/folder-permission-system/databases

# 1. 生成新密碼雜湊（使用方案 2 的步驟 1）
NEW_PASSWORD_HASH="$(cd /opt/folder-permission-system && node generate_hash.js '<新密碼>')"

# 2. 刪除舊的管理員帳號（可選）
sqlite3 system.db "DELETE FROM accounts WHERE username = 'admin';"

# 3. 建立新的管理員帳號
sqlite3 system.db "INSERT INTO accounts (username, password_hash, full_name, role, status, user_database, permission_level) 
VALUES ('admin', '$NEW_PASSWORD_HASH', '系統管理員', 'admin', 'active', 'admin.db', 'editor');"

# 4. 驗證
sqlite3 system.db "SELECT id, username, role, status FROM accounts WHERE username = 'admin';"
```

## 完整檢查清單

執行以下檢查確保系統正常：

```bash
# 1. 檢查資料庫完整性
cd /opt/folder-permission-system/databases
sqlite3 system.db "PRAGMA integrity_check;"

# 2. 檢查帳號狀態
sqlite3 system.db "SELECT username, role, status, 
    CASE 
        WHEN password_hash LIKE '\$argon2%' THEN 'argon2 ✓'
        ELSE '需更新 ✗'
    END as hash_status
FROM accounts;"

# 3. 檢查是否有活躍的管理員
sqlite3 system.db "SELECT COUNT(*) FROM accounts WHERE role = 'admin' AND status = 'active';"

# 4. 檢查應用程式日誌
pm2 logs folder-permission-system --lines 50
# 或
tail -n 50 /var/log/folder-permission-system.log
```

## 常見問題

### Q1: 提示「使用者名稱或密碼錯誤」

**可能原因**：
- 密碼雜湊格式不匹配（bcrypt vs argon2）
- 密碼確實錯誤

**解決方法**：
1. 使用 `check_accounts.sh` 檢查密碼格式
2. 使用 `reset_password.sh` 重置密碼

### Q2: 提示「帳號尚未通過審核」

**解決方法**：
```bash
sqlite3 /opt/folder-permission-system/databases/system.db \
  "UPDATE accounts SET status = 'active' WHERE username = 'your_username';"
```

### Q3: 提示「帳號狀態異常」

**解決方法**：
```bash
# 檢查狀態
sqlite3 /opt/folder-permission-system/databases/system.db \
  "SELECT username, status FROM accounts WHERE username = 'your_username';"

# 設為 active
sqlite3 /opt/folder-permission-system/databases/system.db \
  "UPDATE accounts SET status = 'active' WHERE username = 'your_username';"
```

### Q4: 找不到 argon2 模組

**解決方法**：
```bash
cd /opt/folder-permission-system
npm install argon2
```

### Q5: 提示「資料庫不存在：/opt/folder-permission-system/databases/main.db」

**原因**：系統使用 `system.db` 而不是 `main.db`

**解決方法**：
- 腳本已自動檢測，會優先使用 `system.db`
- 如果仍出現錯誤，請確認資料庫目錄中是否有 `system.db` 檔案
- 手動檢查：`ls -lh /opt/folder-permission-system/databases/*.db`

## 快速修復指令（一鍵執行）

如果需要快速修復管理員帳號，可以執行：

```bash
# 使用預設密碼重置管理員帳號
sudo ./reset_password.sh admin   # 依提示輸入新密碼（至少 10 字元、含三類字元）
```

然後使用以下帳號登入：
- **使用者名稱**：`admin`
- **密碼**：重設時自行設定的新密碼（登入後系統會要求再改一次）

**強烈建議**：登入後立即修改密碼！

## 技術說明

### 密碼雜湊格式識別

- **argon2**：以 `$argon2id$` 或 `$argon2i$` 開頭
- **bcrypt**：以 `$2a$`、`$2b$` 或 `$2y$` 開頭

### 資料庫位置

- 系統資料庫：`/opt/folder-permission-system/databases/system.db`（或 `main.db`）
- 帳號表：`accounts`
- 主要欄位：`username`, `password_hash`, `role`, `status`

**注意**：腳本會自動檢測系統資料庫，優先使用 `system.db`，如果不存在則使用 `main.db`。
